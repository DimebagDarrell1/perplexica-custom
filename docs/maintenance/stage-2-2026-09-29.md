# Stage two: dependencies, builds, and assets

Completed locally on September 29, 2026. Work stops after this stage for review. Nothing was committed, pushed, published, or deployed.

## Result

The final dependency audit reports zero findings, compared with 333 before the update: 10 critical, 177 high, 126 moderate, and 20 low. These are the audit's dependency-path counts, not 333 distinct application vulnerabilities. An empty audit does not prove the application has no security issues.

Both production builds passed. The final build includes the updated native-module tracing configuration. The combined QA command passes 38 regression tests and TypeScript checks. ESLint runs successfully with zero errors and 34 warnings.

Three targeted resolutions remain in package.json:

- React types are fixed to 18.3.31 so nested dependencies cannot introduce React 19 types into the React 18 application.
- Transformers uses Sharp 0.35.5 or a compatible patch instead of the vulnerable 0.34 line. Its image-resize path passed a runtime check. The Transformers major version is unchanged.
- The legacy esbuild-kit development dependency uses patched esbuild 0.25.12 or a compatible patch. Drizzle's schema-export command passed without connecting to or modifying the database.

ESLint stays on 9.39.5 because the React, import, and accessibility plugins used by the current Next config do not declare ESLint 10 compatibility. ESLint 9 is deprecated upstream. This compatibility constraint is recorded rather than forcing an unsupported plugin combination.

## Application changes

DOCX uploads now use Mammoth, which was already a direct dependency. The redundant Office parser and its vulnerable file-type/PDF dependency paths were removed. PDF and plain-text uploads retain their existing parsers. Added integration tests exercise real DOCX extraction, table text, Unicode text, PDF generation, two-page PDF extraction, and passage storage with an in-memory embedding stub. No model API was called.

The provider-selection dialog no longer updates state inside useMemo. Defaults initialize with the form, and selecting another provider resets fields in the selection handler. Browser checks verified that switching from OpenAI to Ollama and back clears temporary values and restores the correct defaults without saving a connection.

All 34 missing tracked public assets were restored from this fork's HEAD, including icons, the editorial font, weather artwork, and screenshots. Every restored file was compared byte-for-byte with Git history. Existing files were not overwritten.

## Tooling and packaging

- Replaced the removed `next lint` command and legacy .eslintrc.json with ESLint's flat configuration.
- Added `typecheck`, `qa`, and `browser:install` scripts. Type checking first regenerates Next route types to avoid stale generated declarations.
- Kept the new React compiler diagnostics for state updates in effects, ref access, and immutability visible as warnings. Basic hook rules still fail on errors. A broad React state rewrite is outside this stage.
- Preserved full-page navigation on the two new-chat links. Narrow lint comments explain that the reload resets the shared chat provider.
- Declared Yarn 1.22.22, marked the application private, and documented the Node 22.13 through 24 runtime range. `.nvmrc` and both Dockerfiles select Node 24.21.0. The host Node installation was not changed; local tests used Node 22.22.3.
- Updated Docker base images to `node:24.21.0-bookworm-slim` and added native build tools to the builder stages.
- Fixed the slim image to copy the locked Playwright packages and run their CLI directly. It no longer lets npx select a different Playwright version at image-build time.
- Added Linux ARM64 and nested PDF canvas packages to standalone output tracing.
- Expanded .dockerignore to exclude Git metadata, build output, local data, uploads, environment files, and legacy config.toml from build contexts.
- Removed the incorrect `:Perplexica` subdirectory from the test Compose Git build URL. The test instance's port and data volume were preserved.

## CI changes

A new quality workflow runs frozen-lockfile installation, lint, type checking, regression tests, production build, and the locked-browser launch check. It uses isolated test data and read-only repository permissions. Separate jobs build both full and slim Docker images and check their packaged browsers without publishing them.

GitHub Actions references were upgraded and pinned to verified commit SHAs. The inherited Docker publishing workflow still names upstream's registry, so its jobs are guarded to prevent this fork from publishing to that registry. No custom registry was invented or configured.

The workflow YAML files parse successfully. The GitHub jobs have not run because these changes have not been pushed. Docker is not installed on this Mac, so neither Linux container build was executed locally. Container results remain a CI verification requirement.

## Local commands and preview

From the application directory, use the pinned Node version and Yarn 1.22.22:

```sh
yarn install --frozen-lockfile
yarn browser:install
yarn qa
yarn build
```

If Yarn is not installed, `npx --yes yarn@1.22.22` can replace `yarn` in these commands. The local verification used a temporary Yarn installation, not a global package-manager change.
