# Stage one: search correctness and safer content handling

Completed locally on September 26, 2026. This stage changes search result handling, uploaded-document ranking, URL fetching, and answer rendering. No dependencies were installed or upgraded. Nothing was committed, pushed, or deployed.

## Changes

### Tool calls keep the correct results

Parallel research actions now return results in the order of the original tool calls. Previously, completion order could attach one tool's result to another tool's call ID. Each action also validates its arguments against its existing schema before executing. The redundant `type` argument was removed from the web-search schema because the tool name already identifies the action.

Files: `src/lib/agents/search/researcher/actions/registry.ts` and `webSearch.ts`.

### Sources retain their identity

Search results from different URLs no longer merge merely because they share a title. URL normalization preserves case in paths and query values. Evidence deduplication also preserves case-sensitive differences in passage text. These changes prevent one source's content from being attached to another source's citation.

Existing removal of tracking parameters and fragments remains in place.

File: `src/lib/agents/search/resultUtils.ts`.

### Uploaded-document ranking preserves passages

Ranking now identifies passages by their stable record index within the loaded store. The previous hash depended on the query's similarity score and did not reliably include the nested passage data. This could collapse different passages or duplicate the same passage across queries.

Multi-query results now use reciprocal-rank fusion, summing `1 / (rank + 60)` with ranks starting at one. Repeated file IDs are loaded once. Identical text in different files retains both file identities. Existing uploaded files and embeddings were not modified or regenerated.

File: `src/lib/uploads/store.ts`.

### Fetch validation applies to the actual connection

The native scraper uses a shared HTTP/HTTPS transport that validates DNS answers inside the socket lookup. The connection uses those checked addresses. Each redirect receives the same checks, and mixed public/private DNS answers are rejected. This closes the gap between checking a hostname and separately resolving it again for the connection.

URL checks now handle expanded IPv6, IPv4-mapped IPv6, special-purpose transition addresses, and trailing-dot local names. The old five-minute DNS safety cache was removed.

Responses have a 10 MB limit on both transferred and decompressed content, a 15-second deadline, and at most five redirects. Size checks happen while reading the body. Existing abort signals are respected, including before a request starts and after a cancelled Firecrawl attempt.

Browser extraction routes HTTP requests through this same transport instead of allowing Chromium to resolve and connect independently. It blocks service workers, WebSockets, non-GET requests, images, media, and fonts. Each extraction has a 30-second deadline, five concurrent requests, a 100-request limit, and a 30 MB content budget. Browser contexts close on failure or cancellation. Redirected HTML keeps the final source URL and receives a base URL for relative resources.

Files: `src/lib/web/urlSafety.ts`, new `safeFetch.ts` and `browserNetwork.ts`, and `src/lib/scraper.ts`.

### Answers cannot supply active raw HTML or arbitrary citation links

Raw HTML in answers displays as text instead of creating active elements. The application's restricted reasoning and numbered-citation tags still work. Ordinary Markdown and code blocks remain readable.

Citation tags carry a source index rather than interpolating a URL into HTML. The renderer resolves that index against the answer's actual source list. Model-supplied citation destinations and labels are not used. Markdown links, citations, and source cards accept absolute HTTP/HTTPS URLs without embedded credentials; unsafe schemes are rejected. External source links use `noopener noreferrer`. Uploaded-file citations render as numbered text instead of invalid browser links.

Citation matching now targets numeric reference groups and leaves ordinary Markdown links intact.

Files: `src/components/MessageBox.tsx`, `MessageSources.tsx`, `MessageRenderer/Citation.tsx`, new `MessageRenderer/safeHtml.ts`, new `src/lib/web/safeLinks.ts`, and `src/lib/hooks/useChat.tsx`.

## Limits and compatibility

This was not a full end-to-end search using live model providers. No paid model requests were made. The UI check used an isolated answer fixture rather than the complete running application.

The local Playwright 1.59.1 installation expects Chromium headless revision 1217, which is absent. Browser verification explicitly used the already-cached revision 1223. Normal browser fallback still needs its package/browser installation aligned in the dependency stage.

Firecrawl runs in a separate service and performs its own DNS resolution and network requests. The application validates the initial URL, but these transport changes do not control Firecrawl's outbound network. Its network isolation needs separate review.

Browser fallback now permits public GET requests only. Pages that depend on POST requests, browser cookies forwarded to the native transport, or blocked resource types may yield less content. These application checks also do not replace operating-system or container network isolation.

The existing lint/build tooling issues and missing tracked public assets remain for stage two. No production build or deployment was claimed in this stage.
