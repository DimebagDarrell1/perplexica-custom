# Stage 5: runtime and CI verification

Local work completed on September 30, 2026. Docker builds, remote CI, and live
service verification remain pending. Nothing was committed, pushed, or deployed.
Jev remains disabled. The three existing files under `data/` match their hashes
from the start of this stage.

## Changes

- Upgraded `better-sqlite3` from the locked 11.10.0 release to an exact 13.0.3
  dependency and updated `yarn.lock`. The fresh Node 24.21.0 build passed, but
  its running server aborted inside a SQLite statement destructor with
  `RemoveEnvironmentCleanupHook: Assertion failed: (env) != nullptr`. The new
  driver passed the same runtime check. Its N-API implementation replaces the
  older addon mechanism and removes the `prebuild-install` dependency. See the
  [upstream v13 release](https://github.com/WiseLibs/better-sqlite3/releases/tag/v13.0.0)
  and [v13.0.3 release](https://github.com/WiseLibs/better-sqlite3/releases/tag/v13.0.3).
- Added a database compatibility test using a disposable legacy-schema database.
  It checks migration of saved questions and answers, Drizzle inserts and
  updates, cancelled status, JSON and Unicode preservation, deletion, database
  integrity, and repeated statement cleanup. The child process must exit
  normally. It passed on both Node 22.22.3 and Node 24.21.0.
- Fixed misleading service health results. Firecrawl now checks its
  `/v0/health/liveness` endpoint and requires successful JSON with `status: ok`.
  SearXNG requires successful search JSON containing a `results` array. Both
  reject redirects. Previously, Firecrawl accepted 401 and 404 responses, while
  SearXNG could accept a login page with HTTP 200. The Firecrawl endpoint follows
  its [upstream routes](https://github.com/firecrawl/firecrawl/blob/main/apps/api/src/routes/v0.ts).
- Added regression cases for HTTP errors, HTML, invalid JSON shapes, and
  redirects, plus successful service responses.
- Added `scripts/check-runtime.mjs` for disposable localhost instances. It
  checks an empty readable chats database, page rendering, packaged JavaScript
  and CSS, health response consistency, and disabled optional providers. Its
  bundled-search option also checks SearXNG configuration and a JSON search.
- Extended CI to start the standalone app and both Docker variants after
  building. The full image also gets the bundled-search check. Failed container
  checks print logs, and disposable containers are removed afterward. Existing
  Chromium checks remain. Updated the service-verification documentation to
  explain what liveness does and does not prove.

installation and the project's existing database were not used for migrations.

checksum verified. The final workspace dependencies were refreshed with a
frozen-lockfile install under the existing Node 22 runtime.
